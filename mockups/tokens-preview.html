tokens.css — Direction: Instrument

Chrome is achromatic; colour is data. Structure comes from one cool graphite ramp. Hue appears only where it answers a question about the data — a classification state, a judge verdict, a confidence level, a drift signal.

Annotator and console are the same palette at two settings: data-tone (light/dark) and data-density (comfortable/compact), with data-surface="annotator" and data-surface="console" as presets for the two standard pairings.

Use the preset or the axes, never both on one element. A light, dense console for print or screenshots is data-tone="light" data-density="compact" with no data-surface — demonstrated in §8.

10 · Rules this file enforces

  1. Screens use semantic tokens only. Reaching for --graphite-700 or --teal-400 in a screen means a gap in tokens.css — edit tokens.css, not the screen.
  2. No ad-hoc colour, font, spacing, or radius values anywhere. None.
  3. Never hard-code a light or dark value. Set data-tone and let the tokens resolve.
  4. A token whose value depends on tone must be declared in full inside both tone blocks. CSS resolves var() inside a custom property at the element where it is declared, not where it is used — so an alias parked on :root silently keeps its light value forever inside a dark scope.
  5. If a colour on screen doesn't answer a question about the data, remove it. There is no brand colour.
  6. Elevation is hairlines and one-step background shifts. A shadow means the thing genuinely floats.
  7. Money, IDs, latencies, and token counts are mono and achromatic. Numbers earn colour only when the colour is the finding.
  8. Judge-authored content is violet; human-authored content is graphite. That distinction is evidence, not decoration.
