# Plan — M0 walking skeleton

## Goal
Instantiate every architectural pattern CONVENTIONS.md names, proven through one thin
end-to-end thread, so that a fresh clone plus `docker compose up` yields a running
system whose guts are observable: `POST /v1/classify/{id}` authenticated by a hashed
scoped key, validated by a contract, served by a deterministic fake provider behind the
`ModelProvider` port and the single `llm/` gateway (timeout, retry+jitter, breaker),
persisted as a `tr_` trace row carrying its `request_id`, followed by an idempotent
queue job, emitting structured logs and OTel spans into a self-hosted Grafana stack, and
rendered by an unstyled React page that logged in through a real better-auth session.
M0's deliverable is the *pattern*, not the feature: M1 swaps one adapter, it does not
rewrite a path. Serves **M0** of docs/BUILD_SPINE.md in full (no scope beyond it; the
supply-chain CI line is M0 per the amended BUILD_SPINE and SENIORITY_CHECKLIST 10).

Source research: `thoughts/shared/research/2026-08-20_m0-walking-skeleton.md`
(all ten of its open questions were resolved in the 2026-08-20 steering session;
rationale in `thoughts/shared/progress/decisions-log.md`).

## Phase P1 — `packages/contracts` (the type truth)
**Slice goal:** the error taxonomy, the envelope, the id prefixes and the classify
schemas exist before anything can be written dishonestly against them.

Files: `packages/contracts/src/{errors,envelope,ids,classify,index}.ts` + co-located
`*.test.ts`.
- `errors.ts` — the closed `ErrorCode` enum exactly as CONVENTIONS lists it
  (`VALIDATION_ERROR` 422 · `UNAUTHORIZED` 401 · `FORBIDDEN` 403 · `NOT_FOUND` 404 ·
  `IDEMPOTENCY_CONFLICT` 409 · `RATE_LIMITED` 429 retryable · `QUOTA_EXCEEDED` 429
  not retryable · `PROVIDER_TIMEOUT` 504 · `PROVIDER_UNAVAILABLE`/`CIRCUIT_OPEN` 503 ·
  `INTERNAL` 500) with a `Record<ErrorCode, {status, retryable}>` map typed so a new
  code without a map entry fails typecheck.
- `envelope.ts` — `{ data, request_id }` / `{ error: { code, message }, request_id }`
  Zod schemas (ADR-0010: `request_id`, never `trace_id`).
- `ids.ts` — prefix constants `cls_ clv_ tr_ ann_ key_ jud_ ds_ ft_`, branded id types,
  prefixed-ULID generator + parser.
- `classify.ts` — request (`input`, optional metadata) and response (`label`,
  `confidence`, `trace_id`) schemas; `trace_id` lives in `data`.

- [ ] Enum + status/retryable map with an exhaustiveness test
- [ ] Envelope schemas parse a success and a failure fixture; `request_id` required on both
- [ ] Id helpers round-trip, reject wrong prefixes, and sort lexicographically by time
- [ ] Classify schemas exported and OpenAPI-describable (`.openapi()` metadata)
- [ ] Removing a map entry fails `bun run typecheck` (proven once, then reverted)

**Automated verification**
```bash
bun run typecheck && bun test packages/contracts
```
**Manual verification**
- Read `errors.ts` against CONVENTIONS "Error handling": every code present, no extras.

## Phase P4 — the steel thread: port, fake provider, `llm/` gateway, classify
**Slice goal:** M0's centre of gravity. The fake provider is a *peer* of the real one
behind the port, so M1 is an adapter swap.

Files: `apps/api/src/llm/{index,provider.port,fake-provider,retry,breaker,cost}.ts` +
`apps/api/src/llm/provider.contract-test.ts`,
`apps/api/src/middleware/api-key-auth.ts`,
`apps/api/src/routes/public/v1/classify.ts`,
`apps/api/src/services/classify.ts`, `apps/api/src/repositories/traces.ts`.

- [ ] `ModelProvider` port + **shared contract test suite** beside it; the fake adapter
      passes it (M1's real adapter will import the same suite)
- [ ] Deterministic fake: same input → same label/confidence/tokens, no network, no key
- [ ] `llm/` is the ONLY module that may call a provider — enforced by a lint rule or an
      architecture test asserting no `fetch` to a provider outside `src/llm/`
- [ ] Timeout, retry with exponential backoff **+ jitter**, and circuit breaker wired
      around the fake; provider failures translated to the taxonomy inside `llm/`
      (`PROVIDER_TIMEOUT` / `PROVIDER_UNAVAILABLE` / `CIRCUIT_OPEN`), raw errors never
      cross the wire
- [ ] Token/cost accounting computed in `llm/` and returned for span attributes (P6)
- [ ] `Clock` port injected so retry/breaker tests are deterministic (no sleeps)
- [ ] API-key middleware: `llk_` prefix, SHA-256 lookup, status check, **scoped to the
      classifier in the path**; wrong/revoked/foreign key → `UNAUTHORIZED` 401
- [ ] `POST /v1/classify/{classifier_id}` validates via the contracts schema, accepts
      `Idempotency-Key`, and returns `{ data: { label, confidence, trace_id }, request_id }`
- [ ] Trace row persisted on 100% of calls (ADR-0001) with **raw provider payload
      alongside normalized fields**, FK to `clv_`, and the `request_id` column set
- [ ] Log lines on the classify path bind the `tr_` `trace_id` once the row exists
- [ ] **422 proven on the real endpoint**: a malformed body to classify auto-maps to
      `VALIDATION_ERROR` with field-level issues — real contract validation, not a fake
      route that only proves a fake route can throw (D-I)
- [ ] **401 proven on the real endpoint**: missing, malformed, revoked, and
      wrong-classifier keys each return the `UNAUTHORIZED` envelope
- [ ] Integration test on the full classify path through `createApp(deps)` with fakes

## Decisions made
Each line becomes an ADR stub at `/approve_plan`.

- **D-A. Phase ordering front-loads Bun-risk seams (P3 db/auth-schema, P5 pg-boss, P6
  OTel) ahead of polish (P7 web, P8 compose).** These three are the research's named
  risk seams; discovering a Bun incompatibility at M3/M4 is the failure mode M0 exists
  to prevent.
- **D-B. `createApp(deps)` composition root from P2, before there are meaningful deps.**
  Retrofitting a seam after routes exist means rewriting every route's imports; three
  ports (`ModelProvider`, `Clock`, `ErrorReporter`) ship through it at M0.
- **D-C. `ErrorReporter` is a port with a no-op adapter, not a direct Sentry import.**
  Keeps zero-secret boot honest (ADR-0009), keeps Sentry a sink rather than a strategy
  (ADR-0007), and makes the central handler testable without a network.
- **D-D. `request_id` is generated by middleware at P2 and re-sourced from the active
  OTel span at P6.** An explicitly staged seam: the envelope contract (ADR-0010) is
  provable before the tracing stack exists, and only one function changes at P6.
- **D-E. better-auth's tables land in P3's first migration, while its handler and
  session middleware mount at P7.** Schema-first keeps the forward-only migration stream
  single and de-risks the better-auth + Drizzle + Bun seam early; splitting config from
  mounting is the cost. The `role` column is *not* among these tables — it lives on
  `org_members` (D-P).
- **D-F. Resilience primitives are hand-rolled, never libraried — a standing principle,
  not a one-off.** DECIDED 2026-08-21. Covers retry with backoff+jitter, circuit
  breaking, timeouts, and later backpressure and rate limiting. CONVENTIONS already
  names this helper as architecture wearing a small hat: it sits inside `llm/`, the one
  gateway every provider call passes through, and these primitives *are* the Category-5
  artifact the project exists to demonstrate — importing them would hand away the thing
  being showcased. Hand-rolled with an injected `Clock` (D-H) they are also deterministic
  to test without sleeps. **M0 scope is only timeout + retry/backoff+jitter + breaker
  around the fake provider**; backpressure and per-key rate limiting are M2 (BUILD_SPINE
  "Resilience & load baseline") and must not leak forward into this milestone.
- **D-G. The "only `llm/` may call a provider" rule is machine-enforced** (lint rule or
  architecture test), not remembered. It is the rule most likely to erode under M7's
  multi-provider routing.
- **D-H. `Clock` is port #2 at M0.** Retry/breaker tests that sleep are slow and flaky;
  the port makes them deterministic and demonstrates the seam is a pattern, not a
  one-off for the provider.
- **D-I. The taxonomy is proven on real endpoints wherever a real endpoint can prove it;
  only 429 and 500 get synthetic routes, and those are mounted outside `/v1`.** REVISED
  2026-08-21 (the first draft put all four demo routes inside the versioned spec).
  Two reasons. First, `/v1` is a versioned public contract where CONVENTIONS says a
  breaking change means a new version — publishing demo endpoints there and deleting
  them at M2 is self-inflicted contract churn, harmless only because nobody consumes it
  yet, and a poor precedent in a project whose pitch is API discipline. Second, faking
  422 and 401 proves less than the real thing: a synthetic 422 proves a synthetic route
  can throw, whereas a malformed body to classify proves contract-validation
  auto-mapping actually works. `/_demo/rate-limited` and `/_demo/boom` remain synthetic
  because nothing in M0 legitimately produces those codes; they are documented in the
  README rather than the OpenAPI spec, and deleted at M2 when real rate limiting lands.
  BUILD_SPINE's required set (422/401/429/500) is still demonstrated in full across M0 —
  at P4 for the first two, P2 for the last two.
- **D-J. Job attempts are recorded in our own table, not read out of pg-boss internals.**
  CONVENTIONS requires jobs to record attempts; depending on a queue's internal schema
  would couple us to it and break the "swap the queue if k6 proves the need" story.
- **D-K. The container's Bun is the authoritative runtime; the Dockerfiles name it
  explicitly (1.4.0) rather than `latest`, and CI and the host track that number.**
  Per ADR-0009 the app only ever *runs* in a container, so pinning the base image is
  what actually de-risks the Bun-sensitive seams — base-image hygiene consistent with
  ADR-0011's "never `:latest`". With the D-N dev overlay the app and its tests both
  execute against the container's Bun, which narrows the host's remaining role to two
  things: authoring the committed `bun.lock` that CI and the images install from under
  `--frozen-lockfile`, and feeding the editor's TypeScript language server, which
  resolves types from a host `node_modules` and cannot see inside the container. Those
  two are why the host still tracks the container's version rather than drifting.
- **D-L. Seed data is deterministic, including the dev API key.** The README curl must
  work verbatim on a fresh clone; a random key would mean an extra copy-paste step and
  would break the one-command claim. It is a `llk_test_` key on a throwaway local DB.
- **D-M. The base compose file stays on the plain 2.x feature set; the dev overlay may
  use modern features.** The base file is what CI runs and what an AWS/ECS translation
  (ADR-0009) would be read against, so it stays conservative. `infra/docker-compose.dev.yml`
  is developer-machine-only and never runs in CI, so `develop.watch` there costs nothing
  — which resolves the research doc's stale "no `develop.watch`" constraint (that was
  recorded against Compose 2.5.1; the machine has v5.4.0 and `docker compose watch` is
  confirmed present).
- **D-N. The dev inner loop is `compose watch` with `action: sync` plus `bun --hot`
  inside the container — not a bind mount.** Two reasons, both specific to this repo.
  (1) *Monorepo masking:* a bind mount of the repo shadows the image's `/app/node_modules`
  (built for linux) with the host's (built for darwin-arm64), so it must be masked by an
  anonymous volume per workspace that has one — a list that silently grows as workspaces
  are added and breaks confusingly when someone forgets. `sync` copies files in rather
  than mounting over the path, so nothing is shadowed and no masking volumes exist.
  (2) *Resource shape on macOS:* under a bind mount the in-container watcher observes a
  host filesystem across the VM boundary, which is the classic sustained-CPU pattern on
  Docker Desktop; under `sync` the watcher observes the container's own overlayfs while
  compose's host-side watcher uses FSEvents, making the cost bursty (a few KB copied per
  save) rather than continuous. The one real hazard is a `rebuild` rule scoped to a
  source path, which converts every save into a full image build — hence the explicit
  scoping checkbox in P8 rather than trusting whoever writes the file. Dangling images
  from genuine rebuilds are handled by `compose watch --prune`, which defaults on.
  Cost accepted: a small copy latency per save, and watched paths must be declared.
- **D-O. Biome for lint + format**, over ESLint flat config plus plugins. DECIDED
  2026-08-21. One binary covering both jobs, no plugin dependency tree to audit (which
  matters for a repo whose CI runs dependency scanning from M0), and fast enough to sit
  in the inner loop. The `console.log` ban CONVENTIONS requires is a Biome rule. Not a
  STACK_DECISIONS row: it shapes no architecture and is reversible file-by-file.
- **D-P. The `role` column lands on a new `org_members` table at M0, not on
  better-auth's `user` table.** DECIDED 2026-08-21. A role on `user` encodes one global
  role per person, which the tenancy model contradicts: PRODUCT 5.1 has org-scoped roles
  and guest experts who are external people invited into a *specific* org, and the V3
  roadmap has SMEs working across several orgs. Putting it on `user` now and moving it at
  M4 would perform exactly the data migration the "ship the column at M0" decision was
  made to avoid, so the cheap-looking option is not actually cheaper. `orgs` already
  exists at M0; `org_members` is three columns and stays unenforced until M4.
- **D-Q. Postgres ships as one of our containers in every environment, including
  production. The deploy target is subordinate to that, not the other way round.**
  DECIDED 2026-08-21 by the stakeholder, and it **amends ADR-0009**, which assumed a
  portable *managed* Postgres at the deploy target. The trigger was the migrator/app role
  split: `CREATE ROLE` needs privileges a managed addon may withhold, and the append-only
  audit guarantee (SENIORITY_CHECKLIST 9, "DB-grant enforced") is worth little if it holds
  locally but not in production. Owning the container makes the two-role design, the
  grants, and the guarantee identical everywhere, with no environment-specific branch —
  which is ADR-0009's stated principle ("`docker compose up` boots the ENTIRE stack with
  the same images production runs") taken literally rather than its hosting footnote.
  Railway remains the intended host but is now explicitly replaceable: if it cannot run
  our Postgres container with a persistent volume, the host changes, not the code.
  **Accepted cost:** backups, restore testing, and durability become ours rather than an
  addon's. That is not M0 work — M0's Postgres is a throwaway local volume — but it must
  not evaporate: it belongs to M1's CD planning, where a live URL first holds real data.
  Reversible: the app connects by URL, so a managed Postgres remains available later.
